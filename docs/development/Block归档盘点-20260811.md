## 构建环境问题与修复

### 发现的问题

| 问题 | 归档前状态 | 修复 |
| --- | --- | --- |
| Go 来源不确定 | `deploy/block/build.sh` 只调用 PATH 中的 `go`；开发脚本则假定固定 `.tools/go1.26.5`。 | 正式 `build-release.ps1` 下载并校验官方 Go `1.26.5` ZIP，并把已验证 Go 明确传给 Bash；直接调用低层 `build.sh` 必须显式给 `BLOCK_GO_BIN` 与全部受控环境。 |
| 历史模块缓存依赖 | HMI demo 依赖 `.cache/block-v2-runtime-001/gomodcache`，SSH 验证依赖 `.cache/go/gopath/pkg/mod`。 | 模块只下载到本次 state root 的 `GOMODCACHE`，逐 module 执行 `go mod verify` 后 `GOPROXY=off`。 |
| TypeScript 不可审计 | 没有根 `package.json/package-lock` 或 HMI tsconfig，运行时 JS 是否由确定版本编译无法复核。 | 新增根 lock（精确 `typescript: 5.6.3`）和 `apps/block-hmi/tsconfig.json`；两个 TS 输出均做字节级守卫。 |
| 工具环境未封闭 | 临时目录、缓存和交叉编译标志由调用者手工设置，容易混入用户环境。 | bootstrap/state root 统一设置 `TEMP`、`TMP`、`TMPDIR`、`GOTMPDIR`、`GOPATH`、`GOCACHE`、`GOMODCACHE`，固定 `GOENV=off`、`GOWORK=off`、`GO111MODULE=on`、空 `GOROOT`、`GOARM64=v8.0`，清除私有/不安全 Go、Node/npm 与所有继承 `GIT_CONFIG_*` 注入变量；保留 `HTTP(S)_PROXY` 和正常 Git 代理仅作传输路径。release 强制 Linux/arm64、`-mod=readonly`、`-trimpath`、`-buildvcs=false`。 |
| VCS 与缓存身份不明确 | 脏工作树、用户 Go env 或无 owner 的非空缓存可能产生不可复核 hash，或误删外部目录。 | 正式 release 默认拒绝 dirty/untracked 工作树，制品记录 commit/tree/clean 状态；未传 `-StateRoot` 时按版本使用独立 `.cache/block-release-<version>`，而 bootstrap 独立调用才使用 `.cache/block-build`。state root 仅允许仓库根目录 `.cache` 的直接子目录，带 owner marker，拒绝仓库根、卷根、junction 和非拥有的非空目录；空无 marker 目录可安全初始化，`-FreshState` 只删除已有 owner marker 的非空目录。 |
| 生成物回流风险 | 根 ignore 未明确覆盖根/嵌套 `.cache`、`node_modules`、`target` 等。 | `.gitignore` 明确忽略这些生成目录，保留源码、脚本、锁文件和已跟踪运行时资产。 |
| Git Bash 回归夹具的链接降级 | 当前 Windows Git Bash 在默认设置下会把 `ln -s <目录>` 降级为普通目录；回滚测试中的 `current` 不再是链接，`readlink -f` 与 `-L` 断言失真。 | 两个部署回归脚本仅在 `MINGW/MSYS/CYGWIN` 测试环境设置 `MSYS=winsymlinks:native`；Windows 测试 mock 还跳过目录 chmod。真实 Linux 安装/回滚脚本没有改为 Windows 语义。 |
| Git Bash 安装位置假定 | release 原先只尝试固定 `C:\Program Files\Git`，非标准 Git for Windows 安装会失败或误用 WSL/系统 `bash.exe`。 | release 先从 PATH 的 `git.exe` 推导 Git for Windows 根目录，也接受显式 `-GitBash`/`BLOCK_GIT_BASH`；拒绝 WSL/System32 bash，并要求同一安装内可执行的 `cygpath.exe`。 |
| 默认点表回归误判 | 原部署回归用 `float32|fc10` 泛匹配排除模拟器点；但正式默认点表合法包含 `D522` 的 FLOAT32 读点和 `D1000` 的 FC10 DINT 写点。 | 改为逐个排除 legacy `simulatorFloat32` 的 D800–D852 专用地址，保留对正式数值点的验证，不改变任何 PLC 点位或运行逻辑。 |
